# Архитектура

Система состоит из двух частей: мобильного приложения и тонкого сервиса. Требования — в [Requirements.md](Requirements.md).

| Часть | Документ |
|---|---|
| Приложение (Flutter) | [Architecture-app.md](Architecture-app.md) |
| Сервис | [Architecture-service.md](Architecture-service.md) |
| Источники данных: словари, уровни, разметка | [Data-sources.md](Data-sources.md) |

## 1. Кто за что отвечает

| | Приложение | Сервис |
|---|---|---|
| Чтение | Библиотека, рендеринг, позиция | — |
| Разметка текста | Показывает готовую разметку | Предварительная разметка глав (батч) |
| Справочные данные | Подтягивает нужные части по мере необходимости и кэширует | Хранит полные библиотеки для разметки: CEFR-списки слов и прочее |
| Словари | Локальные словари для офлайн-режима | Полные словари |
| Перевод по запросу | Цепочка провайдеров, история | — |
| Повторение, история, профиль | Хранит локально | — |

## 2. Основные правила

1. **Приложение работает без сервиса.** Без сети доступно то, что уже скачано: книги, готовая разметка, локальные словари, справочные данные.
2. **Сервис не хранит данные пользователя.** История, карточки и прогресс живут только в приложении.
3. **Приложение берёт данные с сервиса по мере необходимости**, а не целиком при установке.

## 3. Структура репозитория

```
app/        Flutter-приложение, см. Architecture-app.md
service/    тонкий сервис, см. Architecture-service.md
docs/
```

`service/` лежит в этом же репозитории. Его можно вынести в отдельный репозиторий, когда понадобится.
