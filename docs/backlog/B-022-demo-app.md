# B-022. Демо-приложение со сценариями для отладки визуала

**Статус:** открыт  
**Тип:** инструмент разработки  
**Связано с:** [B-019](B-019-text-highlights.md), [B-020](B-020-reader-colors.md), `app/app`, `core_testing`

## Проблема

Чтобы проверить, как выглядит экран в нужном состоянии, приходится вручную открывать книгу, строить шпаргалку, включать подсветку, тапать по слову. Это долго, и состояние трудно повторить.

## Что хотим

Отдельное мини-приложение с демо-данными. Оно сразу открывает нужную «ситуацию», без нажатий. Пример сценария: «читаем книгу, до этого смотрели шпаргалку, подсветка включена, открыт перевод слова».

- Список сценариев на стартовом экране; сценарий можно выбрать и аргументом запуска, чтобы открывать его сразу.
- Работает на macOS и в эмуляторе.
- Данные фейковые и детерминированные: книга, история, шпаргалка, уровни, переводы.
- Внутри сценария можно продолжать работать как в обычном приложении (тапать, листать).

## Анализ

- Отдельная точка входа (например, `app/app/lib/main_demo.dart` или пакет `app/demo`), которая собирает те же экраны с фейковыми реализациями портов из `core_testing` и in-memory хранилищем.
- Сценарий — значение: начальные данные плюс действия после первого кадра (открыть главу, показать модалку). Выбор: `--dart-define=SCENARIO=reader_lookup_after_cheatsheet`.
- Встроенная демо-книга (короткий текст, CC0 или свой) с заранее известными сложными словами.
- Те же сценарии пригодятся для golden-тестов.
- Состояние вроде «модалка открыта» сейчас живёт внутри экранов. Возможно, экранам понадобятся параметры начального состояния; это меняет их API, отметить в `DECISIONS.md`.

## Вопросы

1. Первый набор сценариев: читалка с подсветками, модалка перевода (слово, фраза, нет перевода), шпаргалка, левая панель, меню шестерёнки. Что ещё?
2. Использовать ли сценарии сразу и для golden-тестов?

## Результат

Задача на каркас демо-приложения и 3–5 сценариев; сценарии добавляются в задачах соответствующих функций.
