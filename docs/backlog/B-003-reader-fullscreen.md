# B-003. Полноэкранное чтение и системные панели

**Статус:** частично: п. 1 (нижний отступ) done 2026-11-23, проверено на Pixel; п. 2 (полноэкранный режим) done в [T-087](../tasks/T-087.md), только Android и iOS; панели не проверены на устройстве  
**Тип:** доработка  
**Связано с:** R-3 в [Requirements.md](../Requirements.md), [B-002](B-002-android-build-debt.md)

## Проблема

На Pixel полоса системной навигации внизу перекрывает текст и кнопку «Next chapter».

Причина: Android 15+ (наш `targetSdk` берётся из Flutter, он выше 35) всегда рисует приложение edge-to-edge, под системными панелями. `ReaderScreen` отдаёт `engine.buildView()` прямо в `Scaffold.body`. `ReaderView` (`reader_simple`) не учитывает `MediaQuery.paddingOf(context).bottom`, и последние строки и `_EdgeButton` уходят под панель. На macOS панелей нет, поэтому там этого не видно.

## Что хотим (как в FBReader)

- При чтении экран полноэкранный: нет ни AppBar, ни системных панелей.
- Тап по пустому месту (не по слову) показывает верхнее меню приложения и системные панели. Повторный тап или начало прокрутки прячет их.
- Тап по слову, как и раньше, открывает перевод и меню не трогает.

## Анализ

**1. Отступы (быстрый фикс, S).** Добавить в список `ReaderView` нижний отступ `MediaQuery.paddingOf(context).bottom` (или `SafeArea(top: false)` вокруг тела). Полчаса работы плюс widget-тест с `MediaQuery(padding: …)`. Нужен и при полноэкранном режиме: когда панели показаны, они не должны закрывать текст, и на macOS ничего не меняется.

**2. Полноэкранный режим (M, примерно 1 задача на день).**
- `reader_api`: новое событие `ReaderEvent`, например `EmptyTapped`, для одиночного тапа не по слову. Сейчас `SimpleReaderEngine.wordTapped` при `wordRangeAt == null` молча выходит; здесь и будем слать событие. Тап по полям вне текста (отступы, `_EdgeButton`-пустышки) тоже должен его давать: `GestureDetector(behavior: translucent)` в `ReaderView`, не мешая выделению текста. Меняется контракт, нужна запись в `DECISIONS.md` обоих пакетов.
- `features/reader`, `ReaderScreen`: состояние «меню видно»; AppBar поверх текста (`extendBodyBehindAppBar` плюс `AnimatedSlide`), а не удаление AppBar из Scaffold: иначе текст при каждом тапе прыгает по высоте и сбивается позиция.
- Системные панели: `SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)` при входе в чтение и показ вместе с меню; `edgeToEdge` при выходе с экрана (`dispose`) и при уходе на библиотеку, настройки, историю (они открываются через `push`). После `resumed` из фона Android может вернуть панели, поэтому режим надо выставить снова.
- На macOS `SystemChrome` ничего не делает; там прячется только AppBar.
- Тесты: widget-тест экрана (тап не по слову → AppBar показан, ещё тап → скрыт; тап по слову → только перевод), тест движка на новое событие. Системные панели проверяются только руками на устройстве.

**Риски.** Боковое меню оглавления (`Drawer`) открывается кнопкой в AppBar: при скрытом меню оно доступно только после тапа. Жест «назад» с края экрана в immersive-режиме работает.
