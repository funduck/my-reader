# План MVP

Требования — в [Requirements.md](Requirements.md), архитектура — в [Architecture.md](Architecture.md).

## 1. Что такое MVP

Я читаю неадаптированную английскую книгу на Android-телефоне каждый день. Перед очередным куском текста открываю разминку и за 2 минуты пробегаю сложные слова. Во время чтения тапаю по незнакомому слову и сразу вижу толкование, даже без сети.

MVP готов, когда я неделю подряд читаю так одну книгу и не открываю другие приложения.

| Входит | Не входит |
|---|---|
| EPUB, оглавление, позиция чтения | FB2, TXT, PDF |
| Тап и выделение → модалка с толкованием | LLM и онлайн-переводчики |
| Офлайн-словарь Wiktionary (EN→EN) | Карточки и интервальное повторение |
| Импорт своих StarDict-словарей (EN→RU) | Тест в конце главы |
| Разминка перед куском текста: список сложных слов | Идиомы и фразовые глаголы в разминке |
| История запросов, переход к месту в книге | Экспорт в CSV и Anki |
| Мини-сервис на Mac, раздаёт пакеты по Wi-Fi | Сервис в интернете, iOS |

## 2. Решения

- **Для кого:** только для себя. UX можно упрощать, онбординг и экран лицензий не нужны.
- **Режим по умолчанию:** EN→EN. Толкования берём из Wiktionary, где у них хорошее покрытие. EN→RU даёт импортированный StarDict.
- **Разминка считается на устройстве.** Нужны только CEFR-таблица и таблица словоформ, которые скачиваются с сервиса. spaCy и сервер для разметки не нужны.
- **Сервис:** Python-скрипты собирают пакеты из открытых данных, простой HTTP-сервер раздаёт их телефону в домашней сети. Позже скрипты переедут в полноценный сервис.
- **Уровень пользователя:** по умолчанию B2, меняется в настройках.
- **Разминка строится по куску текста, а не по главе.** Кусок начинается с текущей позиции. По умолчанию это 10 условных страниц по 300 слов, длина настраивается. Режим «по главам» берёт текст до конца текущей главы.
- **Повторения в MVP нет.** Журнал запросов копится с первого дня, поэтому карточки потом соберутся из готовой истории.

## 3. Вехи

В конце каждой вехи приложение работает на телефоне и умеет больше, чем раньше. Код пишут агенты по задачам из [tasks/](tasks/README.md), сроки и параллельность — в разделе 4.

### M0. Каркас

- `app/`: pub workspace, пакеты `core`, `core_testing`, `reader_api`, `storage_drift`, `app`.
- `bootstrap.dart` с Riverpod-оверрайдами, `go_router`.
- Линтер импортов: `core` не видит Flutter, фичи не видят адаптеры.
- Сборка под macOS и Android, запуск на телефоне.

**Готово:** пустое приложение запускается на Mac и на телефоне, `dart test` в `core` проходит.

### M1. Читалка EPUB

- `format_epub`: метаданные, оглавление, spine, глава → `ContentDocument`.
- `reader_simple`: глава как прокручиваемый список блоков, `SelectableText.rich`, события `PositionChanged`, `TextSelected`, `WordTapped`.
- `Locator` с `TextQuote`, сохранение позиции с дебаунсом.
- `features/library`: импорт файла с устройства, список книг.
- `features/reader`: оглавление, переход по главам.

**Готово:** открываю книгу на телефоне, закрываю приложение, при следующем запуске оказываюсь на том же месте.

### M2. Мини-сервис и пакеты

- `service/build/`: скрипт качает дамп kaikki.org и собирает SQLite-пакеты:
  - `en-en` — толкования, IPA, часть речи, примеры;
  - `en-forms` — словоформа → лемма;
  - `en-levels` — `lemma | pos | cefr | zipf` из CEFR-J, Octanove и wordfreq.
- Пороги Zipf → CEFR для слов вне CEFR-списков: подобрать на словах, где известны оба значения.
- `manifest.json`: id, версия, размер, sha256 каждого пакета.
- Раздача по HTTP на Mac (`service/serve`).

**Готово:** `curl http://<mac>:8080/manifest.json` с телефона возвращает список пакетов. Размер `en-en` измерен; если он больше ~150 МБ, режем редкие слова по Zipf.

### M3. Толкование по тапу и история

- `packs_http`: в настройках задаётся адрес сервиса, приложение скачивает пакеты, проверяет sha256 и хранит их версии. Для Android нужно разрешить cleartext HTTP к локальной сети.
- `text_en`: предложения, токены, лемма через `en-forms`.
- `lookup_wiktionary`: поиск по лемме в `en-en`.
- `LookupSelection` и `ProviderChain` в `core`, пока с одним провайдером.
- `features/lookup_sheet`: модалка открывается сразу со скелетоном, показывает толкование, IPA, часть речи и примеры.
- `LookupJournal` и `TermRepository` в `storage_drift`: каждый запрос пишется с `Locator` и предложением, повторы агрегируются в `Term`.

**Готово:** в авиарежиме тапаю слово, толкование появляется за 300 мс или быстрее. Запрос лежит в базе вместе с контекстом.

### M4. Разминка перед куском текста

- `levels_cefr`: `LevelDictionary` поверх `en-levels`. Уровень слова показывается в модалке.
- `CheatSheetScope` в профиле: `pages(n)`, по умолчанию 10, или `chapter`.
- Выбор куска: от текущего `Locator` набираем блоки `ContentDocument` до нужного числа слов, при необходимости переходя в следующую главу. В режиме `chapter` — до конца текущей главы.
- `BuildCheatSheet` для куска:
  1. токены куска → леммы;
  2. уровень каждой леммы;
  3. оставляем слова выше уровня пользователя;
  4. убираем то, что уже есть в истории;
  5. ранжируем: уровень выше, Zipf ниже, чаще встречается в куске;
  6. берём 15 первых, к каждому — толкование из `en-en` и первое предложение из куска.
- `features/cheatsheet`: кнопка «Разминка» в читалке строит список слов для куска от текущей позиции. Тап по слову открывает ту же модалку и пишет запрос в историю.
- Уровень пользователя и размер куска в настройках.

**Готово:** перед очередным куском открываю разминку, вижу 10–20 слов, которые действительно не знаю, и пробегаю их за 2 минуты. Доля слов, которые я и так знаю, — на глаз меньше трети.

### M5. Свои словари StarDict

- `lookup_stardict`: импорт `.ifo` + `.idx` + `.dict`/`.dict.dz`, `.dz` распаковывается при импорте, бинарный поиск по `.idx`.
- Статья показывается как есть: plain text или простой HTML.
- Переключатель EN→EN / EN→RU в модалке, порядок провайдеров и фолбэк в настройках.

**Готово:** импортирую свой EN→RU словарь, в модалке переключаюсь на русский перевод.

### M6. История и обкатка

- `features/history`: список запросов, фильтр по книге, счётчик повторов.
- Переход из истории к месту в книге по `Locator`.
- Неделя ежедневного чтения, исправление того, что мешает.

**Готово:** выполнен критерий из раздела 1.

Что видно по диаграмме:

- **Сервис не зависит от приложения.** Поток «Сервис» стартует в первый день вместе с каркасом и закрывается за пять дней.
- **Главное узкое место — читалка.** Каркас → порты ядра → `format_epub` и `reader_simple` → экран чтения → связка с модалкой → разминка. Остальные потоки успевают раньше и ждут её.
- **Пик — волна 5, 11 задач сразу.** Список волн — в [tasks/README.md](tasks/README.md#волны).
- **Предел ставит ревью, а не агенты.** Сколько дней займёт код при разном числе одновременных агентов:

| Агентов одновременно | Дней до готового кода |
|---|---|
| без ограничений | 10 |
| 6 | 10 |
| 4 | 13 |
| 3 | 17 |
| 2 | 25 |

Разумный режим — 4 агента: почти тот же срок, а ревью остаётся посильным. После кода добавляется настройка разминки (1 день) и неделя обкатки.

## 5. Риски

| Риск | Что делаем |
|---|---|
| `en-en` слишком большой для телефона | Измеряем в M2, режем по Zipf и по полям |
| Разминка показывает знакомые слова | Подбираем пороги в M4 на реальной книге; кнопка «знаю» — первое улучшение после MVP |
| `SelectableText` плохо работает с тапом по слову и длинными главами | Проверяем в M1 на самой длинной главе; запасной вариант — свой рендерер на `TextPainter` |
| Лемматизация по таблице ошибается | `Term` пересобирается из журнала, правила можно поменять позже без потери данных |

## 6. После MVP

В порядке приоритета:

1. Кнопка «знаю» в модалке и в разминке.
2. Карточки и SM-2 из накопленной истории.
3. Фразовые глаголы и идиомы в разминке (разметка на сервисе).
4. LLM-провайдер для объяснения выражений в контексте.
5. Тест в конце главы.
