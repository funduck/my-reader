# План MVP

Требования — в [Requirements.md](Requirements.md), архитектура — в [Architecture.md](Architecture.md).

## 1. Что такое MVP

Я читаю неадаптированную английскую книгу каждый день. В MVP — на Mac, телефон — следующий шаг. Перед очередным куском текста открываю разминку и за 2 минуты пробегаю сложные слова. Во время чтения тапаю по незнакомому слову и сразу вижу толкование, даже без сети.

MVP готов, когда я неделю подряд читаю так одну книгу и не открываю другие приложения.

| Входит | Не входит |
|---|---|
| EPUB, оглавление, позиция чтения | FB2, TXT, PDF |
| Тап и выделение → модалка с толкованием | LLM и онлайн-переводчики |
| Офлайн-словарь Wiktionary (EN→EN) | Карточки и интервальное повторение |
| Импорт своих StarDict-словарей (EN→RU) | Тест в конце главы |
| Разминка перед куском текста: список сложных слов | Идиомы и фразовые глаголы в разминке |
| История запросов, переход к месту в книге | Экспорт в CSV и Anki |
| Мини-сервис на Mac, раздаёт пакеты | Android, iOS, сервис в интернете |
| Настройки чтения: шрифт, интервал, день и ночь, фон, листание экранами | Постраничная вёрстка |

## 2. Решения

- **Платформа MVP — macOS.** На Mac проще собирать, тестировать и проверять, эмулятор не нужен. Android — первым делом после MVP.
- **Для кого:** только для себя. UX можно упрощать, онбординг и экран лицензий не нужны.
- **Режим по умолчанию:** EN→EN. Толкования берём из Wiktionary, где у них хорошее покрытие. EN→RU даёт импортированный StarDict.
- **Разминка считается на устройстве.** Нужны только CEFR-таблица и таблица словоформ, которые скачиваются с сервиса. spaCy и сервер для разметки не нужны.
- **Сервис:** Python-скрипты собирают пакеты из открытых данных, простой HTTP-сервер на том же Mac раздаёт их приложению. Позже скрипты переедут в полноценный сервис.
- **Уровень пользователя:** по умолчанию B2, меняется в настройках.
- **Разминка строится по куску текста, а не по главе.** Кусок начинается с текущей позиции. По умолчанию это 10 условных страниц по 300 слов, длина настраивается. Режим «по главам» берёт текст до конца текущей главы.
- **Повторения в MVP нет.** Журнал запросов копится с первого дня, поэтому карточки потом соберутся из готовой истории.

## 3. Вехи

В конце каждой вехи приложение работает на Mac и умеет больше, чем раньше. Код пишут агенты по задачам из [tasks/](tasks/README.md), сроки и параллельность — в разделе 4.

### M0. Каркас

- `app/`: pub workspace, пакеты `core`, `core_testing`, `reader_api`, `storage_drift`, `app`.
- `bootstrap.dart` с Riverpod-оверрайдами, `go_router`.
- Линтер импортов: `core` не видит Flutter, фичи не видят адаптеры.
- Сборка под macOS.

**Готово:** пустое приложение запускается на Mac, `dart test` в `core` проходит.

### M1. Читалка EPUB

- `format_epub`: метаданные, оглавление, spine, глава → `ContentDocument`.
- `reader_simple`: глава как прокручиваемый список блоков, `SelectableText.rich`, события `PositionChanged`, `TextSelected`, `WordTapped`.
- `Locator` с `TextQuote`, сохранение позиции с дебаунсом.
- `features/library`: импорт файла с устройства, список книг.
- `features/reader`: оглавление, переход по главам.

**Готово:** открываю книгу на Mac, закрываю приложение, при следующем запуске оказываюсь на том же месте.

### M2. Мини-сервис и пакеты

- `service/build/`: скрипт качает дамп kaikki.org и собирает SQLite-пакеты:
  - `en-en` — толкования, IPA, часть речи, примеры;
  - `en-forms` — словоформа → лемма;
  - `en-levels` — `lemma | pos | cefr | zipf` из CEFR-J, Octanove и wordfreq.
- Пороги Zipf → CEFR для слов вне CEFR-списков: подобрать на словах, где известны оба значения.
- `manifest.json`: id, версия, размер, sha256 каждого пакета.
- Раздача по HTTP на Mac (`service/serve`).

**Готово:** `curl http://localhost:8080/manifest.json` возвращает список пакетов. Размер `en-en` измерен; если он больше ~150 МБ, режем редкие слова по Zipf.

### M3. Толкование по тапу и история

- `packs_http`: в настройках задаётся адрес сервиса, приложение скачивает пакеты, проверяет sha256 и хранит их версии. Для macOS нужен entitlement на сетевые запросы.
- `text_en`: предложения, токены, лемма через `en-forms`.
- `lookup_wiktionary`: поиск по лемме в `en-en`.
- `LookupSelection` и `ProviderChain` в `core`, пока с одним провайдером.
- `features/lookup_sheet`: модалка открывается сразу со скелетоном, показывает толкование, IPA, часть речи и примеры.
- `LookupJournal` и `TermRepository` в `storage_drift`: каждый запрос пишется с `Locator` и предложением, повторы агрегируются в `Term`.

**Готово:** с остановленным сервисом и без сети тапаю слово, толкование появляется за 300 мс или быстрее. Запрос лежит в базе вместе с контекстом.

### M4. Разминка перед куском текста

- `levels_cefr`: `LevelDictionary` поверх `en-levels`. Уровень слова показывается в модалке.
- `CheatSheetScope` в профиле: `pages(n)`, по умолчанию 10, или `chapter`.
- Выбор куска: от текущего `Locator` набираем блоки `ContentDocument` до нужного числа слов, при необходимости переходя в следующую главу. В режиме `chapter` — до конца текущей главы.
- `BuildCheatSheet` для куска:
  1. токены куска → леммы;
  2. уровень каждой леммы;
  3. оставляем слова выше уровня пользователя;
  4. убираем то, что уже есть в истории;
  5. ранжируем: уровень выше, Zipf ниже, чаще встречается в куске;
  6. берём 15 первых, к каждому — толкование из `en-en` и первое предложение из куска.
- `features/cheatsheet`: кнопка «Разминка» в читалке строит список слов для куска от текущей позиции. Тап по слову открывает ту же модалку и пишет запрос в историю.
- Уровень пользователя и размер куска в настройках.

**Готово:** перед очередным куском открываю разминку, вижу 10–20 слов, которые действительно не знаю, и пробегаю их за 2 минуты. Доля слов, которые я и так знаю, — на глаз меньше трети.

### M5. Свои словари StarDict

- `lookup_stardict`: импорт `.ifo` + `.idx` + `.dict`/`.dict.dz`, `.dz` распаковывается при импорте, бинарный поиск по `.idx`.
- Статья показывается как есть: plain text или простой HTML.
- Переключатель EN→EN / EN→RU в модалке, порядок провайдеров и фолбэк в настройках.

**Готово:** импортирую свой EN→RU словарь, в модалке переключаюсь на русский перевод.

### M6. История и обкатка

- `features/history`: список запросов, фильтр по книге, счётчик повторов.
- Переход из истории к месту в книге по `Locator`.
- Неделя ежедневного чтения, исправление того, что мешает.

**Готово:** выполнен критерий из раздела 1.

### M7. Удобство чтения

Чтобы читать было приятно. Можно делать параллельно с обкаткой M6.

Что уже есть: в `reader_api` есть `ReaderSettings` (шрифт, размер, тема light/dark, поля), а `SimpleReaderEngine.applySettings` меняет стиль без перезагрузки главы и сохраняет позицию. Но из UI его никто не вызывает, и настройки нигде не сохраняются. Межстрочный интервал задан константой `ReaderStyle.lineHeight = 1.5`.

| Что | Сложность | Комментарий |
|---|---|---|
| Размер шрифта | просто | Поле уже есть. Нужны слайдер в настройках, сохранение (как `UserProfile`) и вызов `applySettings` при открытии книги и при изменении. |
| Межстрочный интервал | просто | Перенести `lineHeight` из константы в `ReaderSettings`, дальше как с размером шрифта. |
| Режимы «день» и «ночь» | просто | `ReaderTheme.light/dark` уже есть. Нужны переключатель в шапке читалки и в настройках, а тема приложения (шапка, модалка) должна идти за режимом читалки. Автопереключение по времени или по системной теме — отдельный небольшой шаг. |
| Цвет текста и фона для каждого режима | просто | Сейчас цвета зашиты в `ReaderStyle.fromSettings`. Нужно хранить пару «текст и фон» отдельно для дня и ночи, а остальные цвета (ссылки, приглушённый, подсветка) выводить из этой пары. Выбор — из 6–8 готовых палитр, свой цвет через HEX. Полноценный пикер цвета — по желанию. |
| Фон-текстура с лёгким шумом | средне | В комплекте 2–3 бесшовные текстуры (бумага, шум), рисуются через `DecorationImage` с `ImageRepeat.repeat` под списком блоков. Свою картинку можно загрузить через `file_selector` (он уже есть в настройках), файл копируется в каталог приложения. Подвох: на тёмном фоне шум должен быть очень слабым, а текстура с цветом — смешиваться с выбранным цветом фона. Решение: текстура в оттенках серого накладывается на цвет фона с прозрачностью, прозрачность — ползунком. Проверить, не тормозит ли прокрутка длинной главы (`RepaintBoundary`, текстура не перерисовывается при скролле). |
| Яркость экрана | средне на Mac, просто на телефоне | На Android и iOS это плагин `screen_brightness`: яркость окна приложения, без системных настроек. На macOS менять яркость дисплея из приложения нельзя или неудобно, поэтому там делаем затемнение: полупрозрачный чёрный слой поверх текста. Жест «провести по левому краю», как в FBReader, — вместе с листанием, см. ниже. Для MVP на Mac хватит ползунка «затемнение» в ночном режиме. |
| Листание тапом по правому краю | средне (прокрутка экранами) / сложно (настоящие страницы) | Сейчас глава — прокручиваемый список блоков (`ScrollablePositionedList`), страниц нет. **Дёшево:** тап по правой трети экрана (по левой — назад) прокручивает на высоту экрана минус одна строка, с короткой анимацией. Слово по тапу в этих зонах не переводится — переводится по тапу в центре или по выделению. Проблема: нижняя строка может разрезаться пополам. Лечится выравниванием прокрутки по границе строки, на это нужен ещё день. Конфликт с тапом по слову — главный риск, это нужно попробовать руками. **Дорого:** настоящая постраничная вёрстка (разбивка текста на страницы через `TextPainter`, `PageView`, пересчёт при смене шрифта, позиция внутри страницы для `Locator`) — по сути новый рендерер, это несколько дней. Откладываем на после MVP. |

Задачи: [T-080](tasks/T-080.md) — модель настроек, хранение в профиле, отрисовка интервала, цветов, текстуры и затемнения в `reader_simple`; [T-081](tasks/T-081.md) — экран настроек, панель «Аа» и кнопка «день/ночь» в читалке, тема приложения по режиму; дальше параллельно [T-082](tasks/T-082.md) — встроенные текстуры и своя картинка, и [T-083](tasks/T-083.md) — листание тапом по краю и клавишами. Проверка — [U-7](tasks/U-7.md). Итого 3 дня кода. T-083 отложена до U-7.

Добавлено после U-7, параллельно: [T-084](tasks/T-084.md) — шрифт из выбранной папки (на Android — из выбранных файлов: папку SAF не прочитать); [T-085](tasks/T-085.md) — толкование по удержанию 500 мс, подсветка слова сразу при касании; [T-086](tasks/T-086.md) — в историю попадают только толкования, открытые 2 с и дольше. Ещё 3 дня кода. Сложное: в T-084 — доступ к папке в песочнице macOS (копируем выбранный файл), в T-085 — долгое нажатие на Android уже занято выделением.

Затем [T-087](tasks/T-087.md) — полноэкранное чтение на телефоне по [B-003](backlog/B-003-reader-fullscreen.md): меню и системные панели по тапу. На macOS не делаем, там AppBar остаётся.

**Готово:** читаю вечером в ночном режиме на фоне с шумом, крупным шрифтом и с увеличенным интервалом, листаю тапом по правому краю. Настройки сохраняются между запусками.

## 4. Параллельная работа

Каждая задача из [tasks/](tasks/README.md) рассчитана на одного агента (Sonnet). Построчного ревью нет: задачи ведёт оркестратор, а ты проверяешь приложение в шести контрольных точках. Как это устроено — в [tasks/README.md](tasks/README.md#как-работаем). Что видно по диаграмме:

- **Сервис не зависит от приложения.** Поток «Сервис» стартует в первый день вместе с каркасом и закрывается за пять дней.
- **Главное узкое место — читалка.** Каркас → порты ядра → `format_epub` и `reader_simple` → экран чтения → связка с модалкой → разминка. Остальные потоки успевают раньше и ждут её.
- **Пик — волна 5, 11 задач сразу.** Список волн — в [tasks/README.md](tasks/README.md#волны).
- **Больше 6 агентов не нужно.** Сколько дней займёт код при разном числе одновременных агентов:

| Агентов одновременно | Дней до готового кода |
|---|---|
| без ограничений | 10 |
| 6 | 10 |
| 4 | 13 |
| 3 | 17 |
| 2 | 25 |

Оркестратор держит до 6 агентов одновременно. После кода добавляется настройка разминки (1 день) и неделя обкатки.

## 5. Риски

| Риск | Что делаем |
|---|---|
| `en-en` слишком большой для телефона (важно после MVP) | Измеряем в M2, режем по Zipf и по полям |
| Разминка показывает знакомые слова | Подбираем пороги в M4 на реальной книге; кнопка «знаю» — первое улучшение после MVP |
| `SelectableText` плохо работает с тапом по слову и длинными главами | Проверяем в M1 на самой длинной главе; запасной вариант — свой рендерер на `TextPainter` |
| Лемматизация по таблице ошибается | `Term` пересобирается из журнала, правила можно поменять позже без потери данных |

## 6. После MVP

В порядке приоритета:

1. Android: сборка, раздача пакетов по Wi-Fi (`serve --lan`), cleartext HTTP к локальной сети, проверка скорости на телефоне.
2. Кнопка «знаю» в модалке и в разминке.
3. Карточки и SM-2 из накопленной истории.
4. Фразовые глаголы и идиомы в разминке (разметка на сервисе).
5. LLM-провайдер для объяснения выражений в контексте.
6. Тест в конце главы.
