# Решения: features/cheatsheet

Контракты и соглашения пакета, принятые в задачах. Общие правила — в [docs/tasks/AGENT.md](../../../../docs/tasks/AGENT.md#принятые-решения).

- Экран разминки (T-054): `CheatSheetScreen({bookId, onRead, from, onWordTap})` из `package:features_cheatsheet/features_cheatsheet.dart`. `from == null` — сохранённая позиция, иначе начало книги. `onWordTap(context, LookupQuery)` — вызывающий показывает `showLookupSheet` (`router.dart`), так что фича не зависит от `lookup_sheet`; `LookupQuery` содержит слово, предложение из шпаргалки, режим из профиля и `sheet.from` как `locator`. Без `onWordTap` строки не нажимаются.
- `cheatSheetProvider((bookId:, from:))` открывает книгу через `OpenBook` из портов, строит `BuildCheatSheet(generator: cheatSheetGeneratorProvider, ...)`, закрывает книгу. Лист содержит всех кандидатов (`CheatSheetLoad.sheet`); из профиля провайдер слушает только кусок (`cheatSheetProfileProvider.selectAsync((p) => p.scope)`), режим берёт через `get()`. Ошибка книги — `AsyncError`, экран пишет «Не удалось подготовить разминку.». `itemGlossProvider((text:, mode:))` берёт первое значение через `ProviderChain` без записи в журнал (в историю пишется только тап).
- Маршрут: `/cheatsheet/:bookId?locator=<json>` (`encodeLocatorParam`), «Читать» делает `pop`, а без истории — `go` в читалку. Тексты на русском, без l10n.
- В тестах провайдеры с фейками завершаются только через `tester.runAsync` (два круга: лист вместе с профилем, затем толкования строк). Чтение потока фейка (`terms.watchAll().first`) в теле теста — тоже через `tester.runAsync`, иначе тест зависает.
- Отбор, уровень, лимит, «Знаю» (T-099): показ строится в `cheatSheetItemsProvider(request)` (`AsyncValue<List<CheatSheetItem>>`) — `selectCheatSheetItems` над листом из `cheatSheetProvider`, уровнем и `cheatSheetLimit` из `cheatSheetProfileProvider` (поток `ProfileRepository.watch()`) и множеством `cheatSheetKnownProvider(request)` (`hidden` по `CheatSheetItem.text`, живёт, пока открыт экран). Смена уровня, лимита и «Знаю» пересчитывает только его: книга и генератор не вызываются заново. Тест считает вызовы фейкового генератора.
- Над списком — `SegmentedButton`: «Выше уровня» A2/B1/B2/C1 (пишет `UserProfile.level`, то же значение, что «My level» в настройках; если уровень A1/C2, выбранного сегмента нет) и числовое поле «Слов» (T-106; `TextField`, только цифры, по умолчанию 10; пишет `UserProfile.cheatSheetLimit`, когда фокус уходит из поля или нажата Enter; пустое или 0 — возврат к сохранённому, больше 500 — 500). Запись — `profileRepositoryProvider.get()` + `save(copyWith)`, список обновляется по потоку профиля.
- Строка: уровень и `FrequencyBars(bars: zipfBars(item.zipf))` (5 полосок растущей высоты, заполнены первые `bars`; без `zipf` виджета нет; `Semantics` «частотность N из 5»), цитата — `item.example` как есть (её режет генератор, `shortQuote`), справа кнопка «Знаю».
- «Знаю» (`CheatSheetKnown.markKnown(item)`): слово сразу в `hidden`, затем `setTermStatusProvider(termKey(analyzer, item.text), known)` — ключ тот же, что пишут толкования. Ошибка записи — слово возвращается в список, `warning` в лог. `SnackBar` «Undo» (`undo(item)`): слово обратно в список, статус `learning`. Скрытые отметки не переживают экран: следующий лист сам прячет известные термины (`BuildCheatSheet`).
- `SnackBar` с «Undo» (T-105): `persist: false` обязателен. Во Flutter 3.50 у `SnackBar` с `action` по умолчанию `persist: true`, и он не закрывается по таймеру.
- Порог частотности (T-115): `cheatSheetItemsProvider` передаёт в `selectCheatSheetItems` `minBars: profile.highlights.minFrequencyBars`; смена порога пересчитывает только отбор.
- Снимок шпаргалки (T-122, вместо T-118): `CheatSheetSnapshot(book, clock.now().toUtc(), тексты показанных строк)` пишется в `cheatSheetLogProvider` только при нажатии «Читать» (`saveShownCheatSheet(container, request)` в `providers.dart`, внутренняя; читает `cheatSheetItemsProvider`, то есть список с учётом уровня, лимита, «Знаю» и куска). При показе и при смене уровня, лимита, «Знаю» не пишется; выход «назад» ничего не пишет, последней остаётся прежняя шпаргалка. Пустой показанный список — пустой снимок. Пока список грузится или в ошибке — записи нет, «Читать» просто зовёт `onRead`. Сбой записи — `warning` в лог, `onRead` всё равно вызывается; `onRead` зовётся после `await` записи (читалка сразу видит снимок) и только если экран ещё смонтирован. «Читать» — последний элемент списка (`ListView`), а не закреплённая панель; при пустом списке, загрузке и ошибке он стоит после сообщения. Тестам экрана нужны `cheatSheetLogProvider` и `clockProvider`.
- Запись профиля (T-120): только `profileRepository.update((p) => p.copyWith(...своё поле...))`, не `save(get().copyWith)`.
- Кусок текста на экране (по просьбе человека, без задачи): третья группа в `_Controls` — `SegmentedButton` `cheatsheet-scope` («Страниц» / «До конца главы») и при страницах `DropdownButton` `cheatsheet-pages` (1, 2, 3, 5, 10, 15, 20, 30 и текущее значение). Пишет `UserProfile.scope` — то же, что «Cheat sheet piece» в настройках; список страниц продублирован из `features_settings`. Смена куска строит лист заново (книга и генератор), уровень/лимит/«Знаю» — нет. Контролы и заголовок вынесены над `load.when` и берут значения из профиля, поэтому остаются на месте, пока лист пересобирается (крутится только список).
- Метка «переводил» (T-121): строка слова с `CheatSheetItem.lookupCount > 0` показывает `LookedUpMark` (ключ `cheatsheet-looked-up-<text>`, экспортируется): значок `Icons.translate` и `×N`, справа от уровня и частотности; семантика — одна подпись «переводил: N», смысл не держится на цвете. Список строит `BuildCheatSheet`: в генератор идут только `known`, у переведённых не `known` слов проставлен `lookupCount`, и они проходят отбор при любом уровне и частотности (в том числе уровень `unknown` и имена). «Знаю» убирает такое слово, как и любое другое; Undo возвращает его с меткой. Отдельной квоты у переведённых нет: общий список по `zipf` и лимит 20 / 50.
