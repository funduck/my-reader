# Решения: features_reader

Контракты и соглашения пакета, принятые в задачах. Общие правила — в [docs/tasks/AGENT.md](../../../../docs/tasks/AGENT.md#принятые-решения).

- Экран (T-020): `ReaderScreen({bookId, locator})`. `OpenBook` и `SaveProgress` (`core/application`) берутся через `openBookProvider`/`saveProgressProvider`, собранные из общих портов. `OpenBook` → sealed `OpenBookOutcome` (`BookOpened(book, opened, resumeAt)` / `BookNotFound` / `BookFileUnreadable`). `SaveProgress.call(locator, {chapterCount, chapterLengths})`: `percent` — `bookFraction` (по длинам глав, пока они не посчитаны — `(chapter.index + progression) / chapterCount`, см. T-104). Позиция: `locator` маршрута важнее сохранённой; `engine.load(book, bookId:, at:)`. Сохранение — через 1 с после последнего `PositionChanged`, при `paused`/`hidden`/`detached` и в `dispose` (потом движок закрывается). У `ReaderEngine` нет `currentLocator()`, поэтому при закрытии сохраняется последний `PositionChanged` (движок шлёт не чаще раза в 500 мс).
- Толкование (T-047, после T-088): `TextSelected` (слово и фраза) экран отдаёт `lookupPresenterProvider` (`LookupPresenter(context, {text, at, sentence})`), потому что фича не может импортировать `lookup_sheet`. Без override бросает `PortNotWiredError` при тапе (ошибка логируется, читалка работает). Проводит `app` (`buildLookupOverrides`).
- Разминка (T-054): `ReaderScreen({onOpenCheatSheet})` — кнопка «Разминка» в AppBar видна только с колбэком; колбэк получает последний `PositionChanged`, иначе место открытия, иначе начало книги; перед вызовом позиция сохраняется.
- Подсветка (T-071): если `ReaderScreen` открыт с `locator` (из маршрута), после `engine.load` вызывается `engine.highlight(ReaderHighlights(ranges: {HighlightKind.focus: [locator]}))`; без `locator` подсветки нет. Рисуется только при `quote` в локаторе (см. `reader_simple`).
- Кнопки шапки (T-101): `onOpenHistory`, `onOpenSettings` — необязательные `VoidCallback`, как `onOpenCheatSheet`; без них кнопок нет.
- Отображение (T-081): `readerSettingsFrom(DisplayPrefs)` (экспортируется) — `theme` по `mode`, `text`/`background` по `palette`, `BuiltInTexture(id)` → `AssetImage('packages/reader_simple/assets/textures/<id>.png')`, `FileTexture` → `FileImage`, `fontFamily` не трогается. `ReaderScreen` читает профиль через `profileRepositoryProvider` (теперь обязателен в тестах экрана), вызывает `applySettings` после `load` и при каждом изменении `display`. Кнопки шапки «Day / Night» (сразу сохраняет) и «Text» (нижняя панель: A−/A+, интервал, затемнение); правки панели применяются к движку сразу, в профиль пишутся через `displaySaveDebounce` = 300 мс, пока таймер идёт, поток профиля игнорируется. Ключи слайдеров: `line-height`, `dim`.
- Текстура (T-082): `readerSettingsFrom` для `FileTexture` с отсутствующим файлом возвращает `texture == null` и пишет `warning`; проверка — `File.existsSync()` при каждом переводе настроек.
- Подсветка тапа (B-004): пока открыт перевод (`LookupPresenter` не завершился), экран вызывает `engine.highlight` с `focus`-местами `[..._marks, at]`, после закрытия — с `_marks` (T-112; пустой список — `ReaderHighlights.none`; слово дальше живёт как `recent`, T-114); `_marks` — метка из маршрута (T-071) или пусто. Цвет тот же, что у метки из истории (вид `focus`, T-112).
- Только что переведённое (T-114, B-019): после закрытия перевода слово переходит из `focus` в `recent`: движок пульсирует его `recentPulseDuration` = 2,5 с (`reader_api`, T-124) и сам перестаёт рисовать; прежние 10 с (`recentHighlightDuration`) убраны. Экран держит `recent` в своём наборе те же 2,5 с по `Timer` и потом убирает (на вид не влияет, повторный `highlight` с тем же набором движку не уходит). Новый перевод снимает прежнее `recent` сразу и обрывает пульс, `Timer` отменяется и в `dispose`. Тоггл: `profile.highlights.enabled && profile.highlights.recent`, профиль читается при закрытии перевода (`profileRepository.get()`); выключено — подсветки после закрытия нет. `ReaderScreen` вызывает `engine.highlight` только из `_applyHighlights()`: он собирает `ReaderHighlights` из полей по видам (`_marks` + `_looking` — `focus`, `_recent` — `recent`); новый вид добавляется своим полем и строкой в этом методе.
- Шрифт (T-084): `readerSettingsFrom` ставит `fontFamily` из `DisplayPrefs.font`; файла нет — `null` и `warning`. `ReaderScreen` вызывает `loadUserFont` перед первым `applySettings` и при смене шрифта в профиле (применяет, только если за время загрузки настройки не сменились). `bootstrap.dart` загружает сохранённый шрифт до первого кадра.
- Полноэкранное чтение (T-087): только Android и iOS (`defaultTargetPlatform`); на остальных AppBar виден всегда, `ViewTapped` игнорируется, `SystemChrome` не вызывается. На телефоне при открытии меню скрыто (`SystemUiMode.immersiveSticky`), `ViewTapped` переключает меню: AppBar и панели показываются (`edgeToEdge`) и прячутся вместе; начало прокрутки пальцем (`ScrollStartNotification` с `dragDetails`) прячет показанное. AppBar лежит поверх текста (`extendBodyBehindAppBar`), не убирается из `Scaffold` и уезжает вверх `AnimatedSlide` (200 мс); скрытый, он не получает касаний, фокуса и чтения с экрана. Верхний отступ текста — `viewPaddingOf(context).top`, запомненный при скрытом меню и неизменный при показанном (текст не прыгает); подставляется в `MediaQuery.padding.top` тела. Вызовы `SystemChrome` — за интерфейсом `SystemChromeGateway` с `systemChromeProvider` (по умолчанию `PlatformSystemChrome`, в тестах — фейк). `dispose` и кнопки «History», «Settings», «Разминка» возвращают `edgeToEdge`; после возврата на экран (`ModalRoute.isCurrent`) и при `AppLifecycleState.resumed` режим выставляется заново по состоянию меню. Листы (перевод, быстрые настройки) панели не трогают. Тесты, которые жмут кнопки AppBar, на телефонном варианте сначала показывают меню тапом по полю или идут с `TargetPlatform.macOS`.
- Переключатель «Перевод» (T-089): кнопка AppBar (`Icons.translate`) между «Day / Night» и «Аа», тултип `Translate: on` / `Translate: off`. Включено — заливка `secondaryContainer` и значок-галочка (`Badge`), не только цвет. Нажатие меняет `DisplayPrefs.translateOnSelect` и сразу сохраняет профиль (как «Day / Night»); `readerSettingsFrom` передаёт его в `ReaderSettings.translateOnSelect`. Кнопка в AppBar: на телефоне видна только с меню (T-087), на macOS всегда.
- Текущая глава в оглавлении (T-100): `_TocDrawer` получает `ValueListenable<int?>` с `chapter.index` последнего `PositionChanged` (до первого события `null` — выделения нет) и выбирает пункт через `currentTocEntry`. Пункт: `ListTile.selected` и жирный шрифт; при открытии `Scrollable.ensureVisible` по центру. Список — `SingleChildScrollView` + `Column`, не `ListView.builder`: нужен `GlobalKey` на пункте, а ленивый список его не строит вне экрана.
- Полоса прогресса (T-104): нижняя панель `_ProgressPanel` — `LinearProgressIndicator` с долей книги и подпись `<заголовок currentTocEntry> · 37%` (без пункта оглавления — только процент; проценты округляются). Лежит поверх текста (`Positioned` в `Stack` тела, текст не сдвигается), уезжает вниз `AnimatedSlide` и, скрытая, не получает касаний, фокуса и чтения с экрана, как AppBar. Видна и скрыта тем же `_menuVisible`; на macOS видна всегда. Нижний системный отступ — `MediaQuery.paddingOf(context).bottom` в её нижнем поле. Позиция — `ValueNotifier<Locator?>`: место открытия, затем последний `PositionChanged`. После открытия книги экран в фоне считает `measureChapterLengths` и кладёт длины в `ValueNotifier<List<int>?>`; пока их нет (или расчёт упал — предупреждение в лог), доля по числу глав. `SaveProgress` получает `chapterLengths`, поэтому библиотека показывает ту же долю, что и панель. `dispose` ставит `_closing`: расчёт останавливается до закрытия книги. Номеров страниц и перемотки по полосе нет.
- Подсветки в листе «Text» (T-116): раздел «Highlights» в `QuickSettingsSheet` — общий выключатель (`highlights-enabled`) и четыре тоггла `highlight-difficult|cheat-sheet|looked-up|recent` («Difficult words», «Cheat sheet», «Looked up», «Just translated»). Лист сам читает и пишет профиль, `ReaderScreen` и `onChanged` не затронуты: `highlightPrefsProvider` (`StreamProvider.autoDispose<HighlightPrefs>` из `profileRepositoryProvider.watch()`), запись сразу, как у «Day / Night» (`get()` → `copyWith(highlights:)` → `save`), без дебаунса; ошибка записи — `severe`, не бросается. Пока профиль не пришёл, тогглы выключены и неактивны; при выключенном общем тогглы видов неактивны (`onChanged == null`), их значения не сбрасываются. Подсветки в тексте рисует не лист: экран смотрит на `UserProfile.highlights` (T-114/T-117/T-119). Лист теперь в `SingleChildScrollView`, ему нужен `ProviderScope` с `profileRepositoryProvider`. Порога частотности в листе нет, он в настройках.
- Сложные слова (T-117): `DifficultWordsTracker` (`difficult_words.dart`) считает набор лемм текущей главы для `ReaderHighlights.words[difficult]`; в `ReaderScreen` — поля `_difficultTracker`, `_difficult`, а `_applyHighlights()` кладёт набор в `words`. Работает при `highlights.enabled && highlights.difficult`: кандидаты главы — один раз через `ChapterDifficultWords.candidates` (асинхронно, `CancelToken` отменяется при смене главы и при выключении), а уровень (`profile.level`), `minFrequencyBars` и пометки «знаю» (`terms.watchAll(status: known)`, язык `en`) только пересобирают набор через `pick`. При выключенном тогле порты `cheatSheetGeneratorProvider` и `termRepositoryProvider` не читаются (берутся лениво), `onChanged` получает пустой набор. Смена главы (`PositionChanged` с другим `ChapterRef`) сразу сбрасывает набор, потом считает новый; та же глава повторно не анализируется. Профиль приходит из `_onProfile` (до проверки `_displayDebounce`), начальный — `profiles.get()` после открытия. Ошибка расчёта — `warning` и пустой набор для этой главы. Расчёт идёт в основном изоляте (анализатор и словарь не передаются в `compute`), но асинхронно; анализ 15 000 слов ~10 мс. Тесты экрана с включённой подсветкой переопределяют `cheatSheetGeneratorProvider` и `termRepositoryProvider`.
- Подсветка слов шпаргалки и переводов (T-119): `word_highlights.dart` — `WordHighlightSource` (читает `cheatSheetLogProvider`, `lookupJournalProvider`, `termRepositoryProvider`, `textAnalyzerProvider`; все четыре теперь обязательны в тестах экрана) отдаёт `WordHighlightSets{cheatSheet, lookedUp}` (леммы, нижний регистр). `cheatSheet` — `CheatSheetSnapshot.lemmas` последнего снимка книги; `lookedUp` — `LookupJournal.watch(LookupFilter(book:, from: shownAt))` (`from` включительно; без снимка — все переводы книги), лемма — `termKey(analyzer, query.text)`, то есть тот же ключ, что `Term.normalized`. Фразы (больше одного слова) в оба набора не попадают; термины со статусом `known` (язык `en`) убираются из обоих. Новый снимок меняет `from` и перезапускает подписку на журнал; пока не пришло первое значение каждого источника, ничего не отдаётся (слова новой шпаргалки не мелькают как «переведённые»). Экран держит только поля и подписки: `_applyHighlights()` — единое место сборки `ReaderHighlights` (`focus`-места `[..._marks, ?_openLookup]` + `words` по видам с учётом `HighlightPrefs`: `enabled && cheatSheet`, `enabled && lookedUp`; пустые наборы в карту не кладутся) и единственный вызов `engine.highlight`; равные подсветки повторно не отправляются. Вызывается после `load`, при смене профиля (`_onProfile`), наборов слов и открытии/закрытии перевода. Остальные виды (`recent`, `difficult`) добавляются в `_applyHighlights` теми же полями.
- Запись профиля (T-120): только `profileRepository.update((p) => p.copyWith(...своё поле...))`, не `save(get().copyWith)`.
