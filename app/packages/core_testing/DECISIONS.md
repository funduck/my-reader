# Решения: core_testing

Контракты и соглашения пакета, принятые в задачах. Общие правила — в [docs/tasks/AGENT.md](../../../docs/tasks/AGENT.md#принятые-решения).

- `core_testing` (T-006): контрактные наборы лежат в `lib/` (`test` — обычная зависимость), адаптеры подключают `core_testing` в `dev_dependencies`. Фабрика во всех наборах — `FutureOr<T> Function() create`, вызывается в `setUp`, возвращает свежий пустой объект. Журнал: фильтр по книге и главе — по `event.query.locator`, `from` включительно, `to` исключительно, порядок «новые сначала»; фильтр по уровню контракт не проверяет (решает T-008). Потоки `watch*` сразу отдают текущее значение. Каскад «удалить книгу — удалить прогресс» проверяет T-007, не контракт.
- Секреты (T-092): порт `SecretStore` — `secretStoreProvider`; контрактный набор `secretStoreContract` и `FakeSecretStore` (`values` — карта для проверок в тестах).
- Журнал фраз (T-093): `phraseJournalContract(create)` и `FakePhraseJournal`. Контракт: повторный `record` того же id не меняет запись, `byBook` — новые сверху, `delete` неизвестного id молчит, `watchAll` отдаёт текущее значение сразу.
- «Знаю» (T-098): `termRepositoryContract` проверяет термин без событий (`lookupCount: 0`, пустые `eventIds`, статус `known`): сохраняется, читается, попадает в `watchAll(status:)`, позже получает события.
