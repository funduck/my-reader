# Решения: reader_api

Контракты и соглашения пакета, принятые в задачах. Общие правила — в [docs/tasks/AGENT.md](../../../docs/tasks/AGENT.md#принятые-решения).

- `reader_api` (T-015): `ReaderEngine` (`buildView`, `load(book, {required bookId, at})` (с T-017), `goTo`, `applySettings`, `highlight(ReaderHighlights)` заменяет прежний набор (T-112), `events` — broadcast, `dispose` один раз). `load` не закрывает `OpenedBook`. `ReaderSettings`: `fontFamily` (null — шрифт движка), `fontSize` = 18, `theme` (`ReaderTheme.light/dark`), `horizontalPadding` = 16; расширять только аддитивно.
- `ReaderSettings` (T-080): `text` и `background` задаются явно, `theme` их не выводит, а определяет только `link`, `highlight` и режим смешивания текстуры. Перевод `DisplayPrefs` → `ReaderSettings`: `theme` по `mode`, цвета по `palette`. `texture` в `copyWith` — функция, `() => null` сбрасывает.
- `ViewTapped` (T-087): `ReaderEvent` с `position` (`Offset` в координатах вида движка, нуль — левый верхний угол) и `size` (`Size` вида; нужен листанию тапом по краю, T-083). Движок шлёт его на одиночный тап в любом месте вида. Не шлёт на удержание (это выделение), сдвиг дальше `kTouchSlop`, двойной тап, тап, который только снимает выделение, и тап по собственным кнопкам вида. Событие приходит через `kDoubleTapTimeout` после отпускания. Событие добавлено в `sealed ReaderEvent`: все `switch` по нему должны его разбирать; экран решает, что с ним делать.
- Выделение (T-088): `WordTapped` удалён, слово и фраза приходят одним `TextSelected` (текст как показан, `Locator` первого символа, предложение). Событие уходит, когда выделение готово (палец или кнопка мыши отпущены после удержания, протяжки маркера или протяжки мышью), по промежуточным изменениям не уходит. `ReaderSettings.translateOnSelect` (по умолчанию `false`): `true` — событие сразу после готовности, выделение сворачивается, тулбара нет; `false` — движок показывает тулбар «Translate» / «Copy», `TextSelected` уходит по «Translate». Поле входит в `==`, `hashCode`, `copyWith`; хранить и вести его в профиле пользователя — задача приложения (T-089).
- Виды подсветки (T-112, B-019): `enum HighlightKind { focus, recent, lookedUp, cheatSheet, difficult }`, **порядок — приоритет**: на слове с несколькими видами рисуется вид с меньшим индексом (`focus` — слово открытого перевода и место из ссылки истории; `recent` — только что переведённое, T-114; `lookedUp`, `cheatSheet`, `difficult` — слова, T-117, T-119). `ReaderHighlights` (`@immutable`, ручной `==`): `ranges` — `Map<HighlightKind, List<Locator>>` (места; нужен `quote`), `words` — `Map<HighlightKind, Set<String>>` (леммы в нижнем регистре, как отдаёт `TextAnalyzer.lemma`; движок сам находит все формы слова в главе). Карты после создания не меняются. `ReaderHighlights.none` и любое значение без мест и слов (`isEmpty`) снимают всё; `==` строгий: `{focus: []}` не равно `none`, поэтому вызывающий, у которого мест нет, передаёт `none`. Вызов заменяет весь набор, а не дополняет; одинаковое значение (по `==`) движок не перерисовывает. Прежний `highlight(List<Locator>)` удалён; чтобы повторить его, передают `ReaderHighlights(ranges: {HighlightKind.focus: places})`. Стиль каждого вида — дело движка (у `reader_simple` — `ReaderStyle.highlightOf`).
